# 派活（后台任务）

额度内、只读或能撤回的活直接派，用卡片告诉用户；超额度、预计超时、会动外面的东西，先交收件箱等用户点头（`skills/inbox`）。

## 派之前看额度

```bash
python3 ~/.openmousse/repo/server/tasks_ctl.py quota
```

- 退出码 0：额度内，直接派。
- 退出码 3：今天的额度用完了。还要派就先交收件箱：`inbox_ctl.py add --kind task --approve-label "派出去" …`，`--why` 写为什么值得多派一个、预计多久，用户点了再派。
- 预计超过单个上限（比如几百页的年报）：也先交收件箱，`--change` 写预计多久；用户同意后 spawn 时 `runTimeoutSeconds` 按同意的时长写。

额度在 `~/.openmousse/server.json` 的 `tasks`（`daily_limit`、`max_minutes`）。真正到点停掉任务的是 OpenClaw 的 `agents.defaults.subagents.runTimeoutSeconds`。

## 怎么派（sessions_spawn）

- `label`：短标题，就是任务卡的标题，比如「BE S1–S3 公式速查表」。说是什么东西，不写"帮用户……"。
- `task`：按这个格式写。任务卡上的「要交」读的就是「要交：」这一行和紧跟着的列表（英文写 `Deliverable:` 也认）：

  ```
  目标：为什么做、给谁用
  要交：交什么（一张表 / 一页 Markdown / 一个文件，放在哪）
  - 要交的细节，一条一行
  约束：只用哪些材料、不做什么、用什么语言
  ```

- `context`：默认 isolated，子会话只看到 task，所以要写清楚；只有细节离不开前面的对话时才 fork。
- `model`：不写就用 `agents.defaults.subagents.model`；工具调用密集、长文档的活可以换更合适的模型。
- `runTimeoutSeconds`：不写，按默认上限到点停；用户在收件箱同意了更长的，按同意的写。
- 要写到外面的（外部系统、云盘、笔记、发邮件、发帖）不交给子会话去做：让它把草稿交回来，你再按收件箱的规矩走。

## 派完

- 回一两句：派给谁、大概多久。比如「派出去了，大概 15 分钟。做完这张卡会变成结果，你先忙别的。」任务正文不要再贴一遍，卡片上有。
- 要几分钟以上的，不要 `sessions_yield` 干等：卡片自己会更新，做完 app 静默推一条。几十秒就能完的小活可以 yield，拿到结果一起回答。
- 结果回到你这里时：说最要紧的一两点就够了，全文在卡片的「看全文」里。
- 用户在卡片上点「改一下」写的意见，直接进那个子会话，不经过你。用户在对话里跟你说要改，就用 `sessions_send` 发给同一个子会话，不要重新派一个。

## 不用派的

- 一两轮能答完的、闲聊、查一个数：自己答。
- 属于某个 Agent 的事：用 `skills/handoff` 转给它，不是派任务。
