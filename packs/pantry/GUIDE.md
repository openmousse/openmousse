# 家里的库存（pantry 功能包）怎么用

表 `pantry` 记家里有什么，一样东西一行。看板上：快过期、该补货了、家里有什么、拍小票 / 记一样 / 出采购单、买菜花费、每周买菜。

```bash
B="python3 ~/.openmousse/repo/server/board_ctl.py"   # 在自己的工作区里跑，不用写 --agent
$B rows query pantry --where 'qty>0' --sort category --limit 100    # 家里现在有什么
```

## 字段

| 字段 | 写什么 |
|---|---|
| name | 名字，写清是什么（「鸡胸 mini fillets」「希腊酸奶 0%」），小票上的缩写翻成人话 |
| qty / unit | 数量和单位：按包装记（2 盒、6 个、1 L），散装按克（800 g） |
| category | 肉蛋 / 奶 / 蔬果 / 主食 / 零食 / 饮品 / 调料 / 其他 |
| price | 这一行花了多少（小票上的价，有折扣写折后的） |
| bought / expires | 买的日期（小票上的日期）/ 到期。小票上没有保质期就按常识估：鲜肉鱼 2–3 天，奶和酸奶 7 天，蔬菜 4–5 天，面包 5 天，鸡蛋 3 周，冷冻 3 个月，干货半年以上；估的在 note 里写「到期是估的」 |
| store | 哪家店 |
| staple / min_qty | 常备的东西（鸡蛋、牛奶、燕麦这类每周都买的）staple 写 true；min_qty 是剩几份就该补（不写 = 用完才算） |
| protein_g | 这一整包的蛋白质克数，按包装或食物库算，算不出留空（「每镑蛋白质」用它） |
| note | 看不清、估的、要核实的，写一句 |

## 什么时候做什么

- **看板按钮发来的照片**（「这是今天的小票，记进库存」带图）：看图读出每一样、数量、价格，`$B rows add pantry --file 行.json` 一次写完。回复一两行：「记好了：11 样，£23.40」，再点出快过期的；认不出的列出来问，别瞎猜。
- **邮件里的电子小票 / 网购生鲜订单**（系统转来的「【自动触发】邮件里的小票」）：同上，按邮件里的明细记，不回问题（没人在看），拿不准的写进 note。同一张小票已经记过（同一天、同一家店、价钱对得上）就跳过。
- **已经有同一样东西**：没过期的就把数量加上（`rows update <id> --inc qty=2`），不重复建行；过期的那行数量清零、再建新行。
- **吃掉 / 用掉的**：用户说吃了什么、记了一餐（他确认过的那次），对得上的扣掉用了多少：`$B rows update <id> --inc qty=-1`（按克记的按克扣）。扣到 0 留着（该补货了会用到），对不上的别硬扣。
- **用户说哪样是常备的**，或者一样东西一个月里买了 3 次以上：staple 设成 true（后者先问一句）。
- **出采购单**（按钮「出采购单」或他问买什么）：先列「该补货了」里的，再按最近几天的配餐缺什么补；家里还有的别写进去。
- **配餐**：两天内到期的先排进最近的一餐，理由里说一句（「鸡胸明天到期，先用掉」）。
- 用户在 app 里也会直接改、删、点「用掉 1 份」：读数据以表为准，别拿你记得的覆盖。

## 提醒

包里带两条提醒（补货：每周六 10:00；快过期：每天 18:00，都是静默推送）。装包的时候各出了一张卡，用户点了同意才开。他说「别提醒了」就 `$B alert list` 找到那条，`$B alert pause <id>`；要改时间就改好规则重新 `alert propose`（同一个 id 会替换原来那条）。
