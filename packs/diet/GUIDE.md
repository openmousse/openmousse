# 饮食记录（diet 功能包）怎么用

饮食记录在服务自己的库里（不是你的数据表）：吃下去的一样一行，带营养和出处；个人食物库存常吃的东西每 100 g（饮品 100 ml）的营养和常用份量；营养目标按日期存。饮食看板的「今日进度」「今日饮食」「本周」读的就是它，「今天」页和小组件也是。

```bash
D="python3 ~/.openmousse/repo/server/diet_ctl.py"   # 在自己的工作区里跑；没有 shell 的用 MCP 的 diet 工具，参数一样
$D day                 # 今天：每餐吃了什么（每一行带 id）、合计、目标、还差多少
$D library --days 30   # 常吃的：次数、常用份量、每 100 g 营养、食物库 id
```

## 记录

- **用户明确让记的**（「我吃了…」「记上」）：`$D add --meal 午餐 --item "<食物库 id 或名字>=克数"`，先不加 `--commit` 看预览；没有估算、没有拿不准的（份量、是哪一样）就加 `--commit` 写进去，回复一句记了什么（每样几克、热量、蛋白质）和批号。有估算的（照片、外卖、查不到的）或拿不准的，把预览给用户看，他说好再 `--commit`。
- **按今天的饮食建议卡记**：`$D log-plan --meal 晚餐`（同一餐不会记两次；`--set 餐.样=克数` 改份量，从 0 数，0 = 这样没吃；`--scale 0.8` 整餐按比例）。app 里的「记录这一餐」走的是同一个接口，不经过你。
- **份量**按克记；食物库里存了份量的可以按个数：`--item "鸡蛋:1 个（去壳）×2"`。
- **一餐的照片**（看板上「拍这一餐」发来的）：认出每样和大概克数，库里有的用库里的营养，其余估：`--item "名字（估算）=克数@kcal,蛋白质,碳水,脂肪" --source photo`。照片一定先给用户看预览。
- **记错了**：`$D undo <批号>`（整批）、`$D rm <id>`、`$D edit <id> --amount 120 --meal 午餐`。
- **你自己想补的**（用户没让记，比如中午了早餐还空着）：不直接写，出一张收件箱卡（inbox skill）。

## 查营养（顺序固定）

1. **个人食物库**：`$D foods --q 名字`。有就用，不再往下查。
2. **包装食品：Open Food Facts**。有条码 `$D lookup --barcode <条码>`，没有就 `$D lookup "名字" --en "English name" --packaged`。品牌、口味、规格都对上了，存进食物库：`$D food-save --from off:<条码> --name "<用户的叫法>" [--portion "1 盒=140"]`。
   用户发来营养标签的照片（看板上「拍标签」）就读标签：`$D food-add --name … --per100 kcal,蛋白质,碳水,脂肪 --source label --note "包装标签"`（标签只有每份的，换算成每 100 g / ml）。
3. **通用食物：CoFID 2021**（英国官方成分表，只有英文名；生熟、带不带皮要选对）：`$D lookup 香蕉 --en "bananas flesh only"`，对上了 `$D food-save --from cofid:<编号> --name 香蕉 [--portion "1 根=120"]`。第一次查会自动从 GOV.UK 下载导入（几秒钟）。
4. **CoFID 没有的：USDA FoodData Central**（服务器的 .env 里有 `USDA_FDC_API_KEY` 才查）：`--from usda:<fdcId>`。
5. **都没有**：按同类估一个，标「估算」（名字里写，或 `--estimated`），回复里说一句是估算。以后拿到标签或条码再 `$D food-update <id> --per100 …` 换成准的。

`$D lookup` 按这个顺序查、查到一个来源就停；`--source off` 只查某一个，`--all` 都查。**不编数字**：查不到就是估算，要标出来。

## 营养目标

`$D targets` 看现在的和改过的。用户说要改：`$D targets set --protein 120 --carb 250 --fat 70 [--kcal 2110] [--from 日期]`（不给 kcal 按 4/4/9 换算）。用户说的直接改。

**碳循环**（训练日、休息日两套目标）：`$D targets set --day-type train …` 和 `--day-type rest …` 各设一套。某天算哪种：标过的（`$D day-type train|rest [--date]`，`auto` 去掉标记）> 日程里排了训练（Agent 的日程键带 `:training:`）> 休息日。`$D day` 和 `/api/diet/day` 的目标已经是那一天那一种的；配餐前看一眼今天算对了没有，临时加练或不练就改标记。

## 和库存（pantry 包）一起用

- 小票进库存时把营养补进食物库（按上面的顺序查），库存的 `protein_g` 按食物库算；查不到的在 note 里写「营养待查」。
- 记完一餐，库存里对得上的扣掉用了的量。

## 数据和署名

- Open Food Facts 是开放数据库许可（ODbL），CoFID 是英国开放政府许可 v3.0，USDA FoodData Central 是公共领域。食物库里每一样都记着出处，给用户讲营养时说一句从哪来的。
- 查过的结果只缓存在这台服务器上；不要把合并后的食物库整份发给别人（分享、好友、名片 Agent 都不带它）。
